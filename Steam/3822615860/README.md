# 缺氧：双回路换热器

版本1.1.4，实现三种建筑，适用于本体及 DLC。使用本机游戏程序集编译。新版功能尚未完成游戏内运行验证。

| 建筑 | 上回路 | 下回路 | 储量（上/下） | 解锁科技 |
|---|---|---|---|---|
| 双回路液体换热器 | 液体，按管道容量，最高100 kg/s | 液体，按管道容量，最高100 kg/s | 5000 / 5000 kg | 液体微调 |
| 液气换热器 | 液体，按管道容量，最高100 kg/s | 气体，最高1 kg/s | 5000 / 100 kg | 液体微调 |
| 双回路气体换热器 | 气体，最高1 kg/s | 气体，最高1 kg/s | 100 / 100 kg | 暖通空调 |

三种建筑均在「实用」菜单，占地宽4×高4，需要地板，建造时间60秒，无需电力。液体微调内部科技ID为 `LiquidTemperature`，暖通空调为 `HVAC`。未完成相应科技时按游戏原版规则锁定。

建造配方分为三个选择栏，共1200 kg：800 kg精炼金属作为基材，200 kg隔热材料（原版 `Insulator` 分类，如陶瓷），200 kg精炼金属作为换热材料。两份精炼金属分别占配方的一栏。

建筑本体使用原版建筑温度机制，与环境正常换热；两路原生 Storage 使用隐藏、密封、隔热的存储修饰器，关闭缓存物质与环境的热传导。建筑本体的温度不会作为两路换热计算的热源或热汇。

使用已确认的双罐、换热模块与输出阀门透明图，菜单使用配套简化图标。建筑贴图按4×4占地适配，当前为静态外观，尚无阀门转动或液位动态动画。美术文件 `assets/exchanger-concept-v1.png` 来自本对话内置 ImageGen 生成的已确认预览；运行时分别选取建筑区和图标区。原版动画组件继续提供建筑状态与选择支持，其储液库画面隐藏。

## 安装

将 `dist/PairedHeatExchangers` 整个文件夹复制到：

```text
文档\Klei\OxygenNotIncluded\mods\Local\PairedHeatExchangers
```

也可解压发布压缩包到 `mods\Local`。该文件夹内应直接包含 DLL、`mod.yaml`、`mod_info.yaml` 和 `assets` 子目录。启动游戏，在模组菜单启用并重启。首次使用建议在测试存档中验证。

## 接口

```text
左上输入A  ┌──────────┐  右上输出A
           │  A回路   │
           │          │
           │  B回路   │
左下输入B  └──────────┘  右下输出B
              自动化输入
```

输入及输出均在建筑角落格子。自动化输入位于底部左数第2格。不接自动化线时默认使能；接线后绿色允许输出，红色停止输出。停止时仍可输入，直到对应液体储量达到5000 kg、气体储量达到100 kg。

每条回路同时只接收一种物质。同一路相同物质在缓存中按质量加权混合温度，两路物质不混合。以缓存混合后的温度作为换热入口温度，不直接使用最新输入包的温度。储存由游戏原生 Storage 管理并随存档保存，拆除时由原生储物处理释放。已存在建筑重载时会更新缓存容量。

## 错误元素与损坏

缓存非空时，若输入物质不同，或输入物质的相态与本回路管道类型不符，显示「元素类型错误」。将错误输入从入口附近泄漏到环境，按原输入包保留质量、温度与病菌；不会塞进缓存或删除。即使缓存已满、自动化为红色，也继续处理错误物质。

持续误输入每5秒通过原版建筑损伤事件扣除1点耐久；两个入口同时误输入也不叠加损伤频率。停止误输入后清除提示并重新计时。耐久耗尽时停止进料和换热输出，按原版规则维修。需要切换回路的物质种类时，先清空原有缓存；空缓存可接收新的合适物质。

## 换热规则

目标出口温度接近另一回路的缓存混合温度，保留2°C端温差。例如在两种物质相态允许时，缓存100°C/200°C → 输出198°C/102°C。温差不超过2°C时，两路均以缓存原温输出。

输出温度另受自身物质相变温度限制，保持在 `最低相变温度+1°C` 至 `最高相变温度−1°C` 之间。目标超界时截取到安全边界，再按两路各自实际温度变化配平流量。例如水的目标温度若超过沸点，实际输出会限制在沸点以下1°C，不会为了满足2°C端温差而输出过热水。缓存温度已经处于安全范围外，或没有可行的安全换热空间时，暂停两路输出。

温差超过2°C时，先计算目标温度，再按相态安全边界分别限制。每个模拟步依据各路实际温度变化、可用储量、管道剩余容量和速率上限计算共同交换热量：

```text
Q = min(可输出质量A × 比热A × 温度变化量A,
        可输出质量B × 比热B × 温度变化量B)
输出质量A = Q / (比热A × 温度变化量A)
输出质量B = Q / (比热B × 温度变化量B)
```

较慢的一侧尽可能达到管道上限，另一侧按比热配平；任一路缺料、出口断开、堵塞或出口管内存在其他元素时，两路同时停止。实际流量也受入口供料及下游影响，不保证每时每刻有一路达到额定上限。程序使用游戏浮点数，存在正常浮点误差。

不改变物质种类。限制的是建筑输出包的温度；液体离开建筑后仍会与下游管道及其已有内容换热，下游环境可能继续导致相变。复用原生病菌合并规则；两路之间不转移病菌。

## 游戏内验收

1. 检查「实用」分类的三种建筑、对应科技锁定、三项1200 kg配方、双罐贴图和菜单图标、4×4占地、四个物质接口以及自动化接口。
2. 先用同种稳定液体在两个温区供料，确认出口接近对方缓存温度且相差2°C。
3. 在液气建筑测试不同比热与供料速率，按实际输出质量核算两路热量。
4. 不接自动化线默认输出；接线红信号、任一出口堵塞、任一侧断料时确认两路同时停出；绿色恢复后继续。
5. 储料后保存、重载，检查两路质量、温度、物质及病菌；拆除时检查储料释放。
6. 用接近沸点/凝固点的液体和接近冷凝点的气体测试，确认输出始终保留1°C相态裕量，同时两路热量平衡。
7. 输入不同元素，核对错误提示、环境泄漏和每5秒1点损伤；缓存满时也要泄漏。纠正供料后恢复，耐久耗尽后应停止运行并可维修。
8. 在冷热环境内观察建筑本体随环境变温，同时断开进出料后的缓存温度不随环境变化；液体容量5000 kg、气体容量100 kg。

新版尚未经过游戏内验证的部分包括贴图在各叠层和预览中的显示、科技解锁与配方选择、错误元素泄漏及维修、存读档及拆除、缓存隔热与建筑本体换热。当前没有专门的运行/堵塞状态面板或动态动画。

## 1.1.1 尺寸更新

三种换热器统一缩为4×4，上回路入口/出口移至顶部第4层，下回路接口仍在底层。旧建筑顶部管线需重新连接。


## 1.1.2 输出修复

缓存位于相变保护的1°C裕量内时，允许按安全方向换热后输出；出口仍受相态裕量与热量守恒约束。入口断料不影响已有缓存。增加输出等待状态，显示空缓存、红信号、管道未连接、出口异种元素、管道已满或相变保护原因。


## 1.1.3 回路隔离与流量更新

阻止原生 Pickupable 堆叠合并跨越换热器缓存，使两路相同物质保持独立质量、温度及病菌。液体缓存每路5000 kg，气体仍为100 kg。接口速率采用对应接口所在管道格的容量（原版读取 ConduitFlow.MaxMass，高压管读取 HPA 的逐格容量查询），最高100 kg/s；输出同时扣除该格已有物质。原版液管仍为10 kg/s、气管仍为1 kg/s。单格100 kg的扩容液管允许最高100 kg/s。

旧存档已混合掉的温差无法还原；修复后需要重新供料建立两路温差。尚未完成游戏内验证。

## 1.1.4 独立收料与浮动信息

液体和气体分别在各自管道更新后收料，收料回调与输出回调分离。缓存未满且来料种类、相态正确时，不受另一侧空缓存、出口堵塞、无出口管道或自动化红灯影响；建筑损坏时仍停止运行。容量检查使用未舍入的实际质量，原生 Storage 进料方法负责库存变更通知。入口管显示为空可能是该格物质已经收进缓存，不代表禁止流入。

兼容已安装的 Ronivan High Pressure Applications 逐格容量查询，四个接口分别限流：普通液管10 kg/s、高压液管100 kg/s；普通气管1 kg/s、高压气管10 kg/s。任何管道最高100 kg/s。未安装该模组时自动使用原版容量。

鼠标悬停建筑时，上、下回路分别显示库存/容量（kg）、入口温度（°C）、实际入流（kg/s）、入口状态、出口温度（°C）及实际出流（kg/s）。入口温度来自本次管道来料，出口温度来自实际成功输出的包，不是目标温度。无来料/出料时对应温度显示“—”、流速为0。数据按原生管道更新周期刷新，暂停时保留最后一次模拟数据。
